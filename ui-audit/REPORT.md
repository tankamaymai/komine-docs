# 小嶺霊園CRM UI/UX診断レポート

**調査日**: 2026-04-22
**対象**: `komine-crm-frontend/` 主要9画面
**方法**: Playwright による各画面の 1440 / 768 / 375 px スクショ収集 + コードベース分析
**調査環境**: ローカル開発（`http://localhost:3000`、管理者アカウント）

---

## 0. 総評

**良いところ**（既に整っている部分）

- **和モダンのデザイントークンが確立済み**：松葉・茶・藍・紅・琥珀の5カラーをCSS変数でライト/ダーク両対応で定義済み（`globals.css`）。Tailwind 標準色との差別化がしっかりしてる
- **PageHeader は統一コンポーネント**：`h-14 md:h-16`、アイコン + タイトル + サブタイトル + UserMenu の構造が全画面で共通
- **サイドバーがモバイルオーバーレイ対応済み**：`md:translate-x-0 -translate-x-full` でドロワー化、`md:hidden` のメニューボタンも実装済み
- **アクセシビリティ基盤**：グローバルfocus ring（3px solid #2563eb）、`aria-label` の付与、`status-*` のパターン記号（●▲■）による色覚バリアフリー
- **レスポンシブガイドラインがCLAUDE.mdに明文化**：375pxファースト、ブレークポイントごとの対応ルールあり

**課題の傾向**（掘り下げポイント）

1. **デザイントークンは定義されているが活用が部分的**：CSS変数外の標準色（`border-gray-200`、`text-gray-500` など）が残存。ブランド外の色が紛れ込みやすい
2. **画面ごとのビジュアルリズムが不揃い**：カード・タブ・KPIボックス・空状態のスタイルが画面ごとに微妙に違う。共通プリミティブが不足
3. **モバイル実装はサイドバーのみ徹底されていて、各画面のコンテンツ領域は画面によってばらつく**
4. **情報密度が高め**：特に `/plots`、`/plots/[id]` でフィールドが詰め込まれている印象

## 1. 問題点一覧（優先度順）

凡例: **🔴 P0**（即時対応推奨）／ **🟠 P1**（短期）／ **🟡 P2**（中期）

### 🔴 P0: アクセシビリティ・ユーザビリティに影響

| # | 画面 | 問題 | 影響 | 提案 |
|---|------|------|------|------|
| 1 | `/plots` モバイル | 区画テーブルが横スクロール必須だが、スクロール可能であることの視覚ヒントがない。「入金」「管理料」「次請求」カラムが見切れる | ユーザーが情報の存在に気付かない | モバイルではカラムを`hidden sm:table-cell`で段階的に非表示。主要4カラム（状態・区画No・契約者・操作）だけ表示するカード化を検討 |
| 2 | ステータスバッジ全般 | `PAYMENT_STATUS_COLORS` で `PartialPaid` と `Unpaid` が同じ色（kohaku）。`Paid` は `text-matsu-dark bg-matsu-50` で薄緑on薄緑に近くコントラスト弱い | 支払い状態が一目で識別できない | 各ステータスを色＋アイコン/記号の組み合わせに。`status-active/warning/attention` のパターン記号方式を流用 |
| 3 | `/yucho` 空状態 | 「対象期間の管理料データが見つかりません」が灰色破線ボーダーの中に薄く表示されているだけで、次のアクションが提示されていない | ユーザーが何をすべきか分からない | イラスト or アイコン + 説明 + 次アクションボタン（年度を変更、など）を含む空状態コンポーネントを作る |
| 4 | `/plots/[id]` | 「未集金額: 0円」のピルが未入金ピルの隣に並んでいるが、装飾が薄く、ラベル/値のヒエラルキーが曖昧。0円/未入金/空欄の区別も不明瞭 | 金額系の重要情報が見落とされやすい | 契約者・金額・ステータスを1つの"サマリーカード"に集約（氏名+未収金額+直近の請求日） |

### 🟠 P1: 一貫性・ブランド整備

| # | 画面 | 問題 | 影響 | 提案 |
|---|------|------|------|------|
| 5 | 全画面 | 日本語ブランド色（松葉・茶等）と Tailwind 標準色（gray-200 等）が混在。`globals.css` の L199-360 でダーク補正を `!important` で上書きしているのは、semantic token の欠如を示唆 | ダーク対応が壊れやすい、新規コンポーネント作成時にトークン選択を迷う | `bg-card` / `bg-muted` / `bg-border` などの semantic token を Tailwind config に追加し、`gray-*` の直接使用を段階的に禁止 |
| 6 | `/collective-burials` vs `/staff` vs `/plot-availability` | KPIカードのスタイルが画面ごとに違う（背景色、ボーダー、影、見出しの大きさ）。`/staff` はボーダー薄+shadowなし、`/plot-availability` はカラフル背景、`/collective-burials` はボーダー強調 | 視覚的一貫性が崩れ、"別システム感"が出る | `<StatCard />` 共通コンポーネントを作って全画面で統一（`komine-crm-frontend/src/components/ui/` に配置） |
| 7 | `/documents` テンプレートカード | 請求書=青、はがき=緑、契約書=黄、許可証=紫、その他=白の5色カードが並ぶ。和モダンパレット（松葉・茶・藍・紅・琥珀）と違うBootstrap的な原色に見える | ブランドと浮く、色選定理由が不明 | 琥珀/松葉/藍/紅/茶の5トークンに置き換え、`bg-{color}-50 border-{color}-200 text-{color}-700` のパターンで統一 |
| 8 | `/masters` タブ9個 | タブが9個横並びでデスクトップでも横が詰まる。`(5) (3) (4)...` のカウント表示も視覚ノイズ | タブ切り替えが使いにくい、どれに何があるか直感的でない | 左サイドセグメンテッド or アコーディオンに変更 / カウントをバッジ化して小さく |
| 9 | ボタンラベル | 「新規登録」「新規追加」「+ 新規登録」「+ 新規追加」など表記揺れ | 同じ操作が別物に見える | 「新規登録」に統一。動詞＋対象（例：「スタッフを追加」）を推奨 |
| 10 | タイポグラフィ | `font-mincho`（明朝）を PageHeader タイトルにのみ使用。本文は system font stack。明朝使用範囲のルールが不明瞭 | 和モダンの表現が断続的 | 見出しは明朝、本文はゴシック、数値はサンセリフに限定、などルール化。`font-sans` / `font-mincho` / `font-numeric` の3種に |

| # | 画面 | 問題 | 提案 |
|---|------|------|------|

## 2. 改善ロードマップ（推奨順序）

### フェーズ1：基盤整備（B: デザインシステム先行）

**工数目安**: 2〜4日

1. **Semantic token の追加**（`tailwind.config.ts`）
   - `card` / `muted` / `border` / `input` / `ring` などshadcn風のトークン
   - 既存の `gray-*` / `white` 直接使用を段階的に置換
2. **共通プリミティブの整備**（`src/components/ui/`）
   - `<StatCard />`：KPI表示用
   - `<EmptyState />`：データ0件時
   - `<StatusBadge />`：支払い/契約状態
   - `<PageSection />`：セクション見出し+コンテンツ
3. **タイポグラフィ・ルール明文化**（CLAUDE.md に追記）
   - `font-mincho` / `font-sans` / `font-numeric` の使い分け

### フェーズ2：P0問題の即時対応

**工数目安**: 2〜3日

4. `/plots` モバイルテーブル改善（Issue #1）
5. `PAYMENT_STATUS_COLORS` の見直し（Issue #2）
6. `/plots/[id]` サマリーカード導入（Issue #4）
7. `<EmptyState />` を `/yucho` 他に適用（Issue #3、#13）

### フェーズ3：一貫性担保

**工数目安**: 3〜5日

8. KPIカードの `<StatCard />` 置き換え（Issue #6）
9. `/documents` テンプレートカラー刷新（Issue #7）
10. `/masters` タブ再構成（Issue #8）
11. ボタンラベル統一（Issue #9）

### フェーズ4：個別画面の集中改善（C: メイン画面集中改善）

**工数目安**: 各2〜3日

12. `/plots` 画面のUX刷新（検索体験、あいうえおタブ見直し、モバイル一覧カード）
13. `/plots/[id]` タブUX改善（モバイル対応、サマリー強化）
14. `/bulk-import` ウィザード化
