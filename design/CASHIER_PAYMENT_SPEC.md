# 窓口入金 仕様書

**バージョン**: v1.0.0  
**実装状況**: 設計確定・未実装  
**最終更新**: 2026-09-08  
**出典**: 2026-07-21 会議議事録 §7「入金管理画面」

## 概要

窓口で現金を受け取ったとき、区画を開かずに、名前（または区画番号）で未払いの請求を探して、残りの全額をその場で入れる。

入金の箱は今の `Payment` のまま。新しい種類のレコードは作らない。区画詳細からの入金も残す。

## 決めたこと

| 項目 | 決定 |
|---|---|
| 入り口 | 左メニュー「業務」に「窓口入金」。専用画面。今の区画詳細の入金は残す |
| 一覧の中身 | 未払いの請求1本＝1行 |
| 種類 | プルダウン。最初は管理料（護持費）。先頭に「全部」 |
| 探す欄 | 名前または区画番号（必須）と、請求の年（最初は今年。空にできる） |
| 名前の当たり方 | 契約者の漢字・かな、故人（埋葬者）の漢字・かな、区画番号・表示番号。部分一致。申込者だけでは当たらない |
| 金額 | 残額の全額。画面では直せない |
| 空の検索 | 名前も区画番号も空なら一覧は出さない |
| 年の初期値 | 今年（日本時間）。空にすると、当たった人の未払いを年をまたいで出す |
| 一部入金・取消・前受 | この画面ではしない。今どおり区画を開く |

## 担当者がすること

1. 左メニューの「窓口入金」を開く。
2. 名前か区画番号を書く。種類は最初から護持費。年は最初から今年。
3. 探す。未払いの行が出る。
4. 行を押す。確認に、名前・区画番号・種類・年・残額・今日の日付が出る。金額は直せない。
5. 保存する。通ればその行は一覧から消える。検索欄はそのまま。次の人の名前を書いて続ける。
6. 種類を「使用料」や「全部」に変える、年を空にする、は必要なときだけ。

見るだけの権限の人は、画面は開けるが保存はできない。

## 名簿の奥で起きること

### 探す

名前・区画番号を空白除去して1文字以上必須。それ未満は探さない。

当たる請求は、削除されていない Billing で、残額（`amount - paid_amount`）が 1円以上。`paid` / `terminated` / `written_off` は出さない。`billed` / `partial_paid` / `overdue` / `pending` は残額があれば出す。

種類が「全部」以外なら `category` がその種類。年が空でなければ、次のいずれかがその年。

- `use_start_year` または `use_end_year` がその年
- どちらも空なら、`billing_date` の年（日本時間）がその年

名前欄の文字列は、次のいずれかに部分一致（大文字小文字は区別しない）。

- その請求の顧客（`Billing.customer`）の `name` / `name_kana`
- その契約区画の契約者（contractor）の `name` / `name_kana`
- その契約区画の埋葬者の `name` / `name_kana`
- 物理区画の `plot_number` / `display_number`

電話番号・住所・申込者だけでは当たらない。

1行に出すもの: 契約者名、区画番号、種類、年、残額。検索文字列が故人に当たった行だけ、故人名も出す。上限 50 件。51件以上当たるときは「結果が多すぎます。名前を長くしてください」とし、一覧は出さない。

残額はサーバが計算する。画面が自分で引き算した結果を信じない。

### 入れる

入金レコードは今の Payment に1件足す。金額を画面から送る今の `POST /payments` は使わない（窓口が金額を決めないため）。窓口用は `POST /payments/settle-remaining`（`billingId` だけ）。

保存1回を1つのまとまりで処理する。

1. 請求を読み直す。残額が 1円未満なら止める。
2. Payment を1件作る。`payment_amount` はいまの残額。`payment_date` は今日（日本時間）。`billing_id` / `contract_plot_id` / `customer_id` は請求側の値。`fee_type` は請求の `category` から今どおりラベルを付ける。金額はクライアントから受け取らない。
3. 今の `recalculateBillingPayments` で、その請求の入金額と状態を計算し直す。
4. 今の `recalculateContractPlotPaymentStatus` で、その区画の未収を計算し直す。

途中で失敗したら、入金は残さない。

## 入力チェック

- 探す文字列は空白除去して1文字以上。
- 種類は「全部」または今の BillingCategory のいずれか。
- 年は空、または 1900〜2200 の整数。
- 入金対象は残額 1円以上の、削除されていない請求。
- 権限は今の入金作成と同じ（operator 以上）。一覧の閲覧は viewer 以上。

## 失敗したとき

| とき | 画面 |
|---|---|
| 名前も区画番号も空 | 「名前か区画番号を書いてください」。一覧は出さない |
| 探したが0件 | 「未払いの請求はありません」 |
| 結果が50件超 | 「結果が多すぎます。名前を長くしてください」。一覧は出さない |
| 行を押したとき、または保存直前に残額が0 | 「すでに入金されています。もう一度探してください」。入金は作らない |
| 想定外 | 「保存できませんでした。もう一度試してください」。途中まで残さない |

## 今回作らないもの

- 一部入金（金額を直して残りの一部だけ入れる）
- 入金の取消・修正
- 前受金（何年分もまとめて先払い）
- ゆうちょ自動連携
- 未収金の印刷専用画面（会議の別項目）
- 名前なしで未払い全員を出す一覧

## 試し方（実装後）

- 名前も区画番号も空だと、一覧は出ず、「名前か区画番号を書いてください」と出る。
- 「田中」で探すと、契約者または故人が田中の、護持費・今年の未払いだけ出る。使用料は出ない。
- 区画番号で探しても当たる。
- 年を空にすると、その人の未払いが年をまたいで出る。
- 種類を「全部」にすると、護持費以外の未払いも出る。
- 行を押して保存すると、残額どおりの入金が1件付く。一覧からその行が消える。区画を開くと未収も減っている。
- 同じ請求へ続けて入れようとすると、「すでに入金されています」で止まる。
- 区画詳細からの1件入金は、今と変わらず動く。
- 見るだけの権限では保存できない。

## 実装の置き場所（目安）

- 画面: `komine-crm-frontend` の `/cashier`。メニュー「窓口入金」。確認ダイアログ。今の入金フォームは使わない（金額を直せるため）
- 探す API: `GET /api/v1/billings/unpaid`（名前・年・種類）。今の `GET /billings` には名前検索を足さない（窓口以外の請求一覧を変えない）
- 入れる API: `POST /api/v1/payments/settle-remaining`。本体は `{ billingId }` だけ。残額・日付・紐付けはサーバが決める。今の `POST /payments`（金額必須）は区画詳細の入金用のまま変えない。ルートは `/:id` より前に置く
- 型: `komine-types` を先に足してから backend / frontend を進める
- 権限: 探すは今の請求一覧と同じ（viewer 以上）。入れるは今の入金作成と同じ（operator 以上）
